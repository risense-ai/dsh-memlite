dsh-memlite 把 memlite 的因果树记忆装进 DeepSeek Harness：相关记忆自动注入 system prompt，零 tool 调用、不阻塞当前轮；数据落本地 JSONL，与 Rust memlite 双向互通。 dsh-memlite brings the memlite causal-tree memory into DeepSeek Harness: relevant memories are injected into the system prompt every turn — zero tool calls, never blocking — stored as local JSONL, fully interoperable with Rust memlite.

01它做什么01What it does

四个机制，全部落在你自己的机器上。

Four mechanisms, all on your own machine.

🧠

自动注入

Auto injection

每轮把与对话相关的记忆拼进 system prompt（可调条数与字符上限）。记忆从对话第二轮起出现，永不阻塞当前轮。

Relevant memories are assembled into the system prompt every turn (tunable count & char cap). Memory appears from the second turn onward and never blocks.

🌳

因果树

Causal tree

记忆是父子链：父=因、子=果。命中即见前因后果，防环 64 层封顶；/memlite-chain 一把取回整条链。

Memories form parent-child chains: parent = cause, child = effect. Hits show their causes and effects; cycles capped at 64 levels; /memlite-chain retrieves a whole chain.

🛡️

敏感闸

Sensitive gate

写前扫描明文口令、API 密钥、身份证、银行卡（Luhn）、手机号、JWT、PEM 私钥——命中即拒，提示改存位置指针。

Pre-write scan for plaintext passwords, API keys, ID numbers, bank cards (Luhn), phone numbers, JWT, PEM keys — hits are rejected with a pointer suggestion.

📝

Obsidian 整合

Obsidian bridge

已有 vault 一键灌成记忆库、库一键导出为 vault、双向同步态一目了然——笔记存量直接变 AI 记忆。

Turn an existing vault into AI memory in one command, export the library back to a vault, and see bidirectional sync states at a glance.

🔄

git 同步

Git sync

白名单 add + pathspec commit（不卷走你已暂存的改动）+ rebase --autostash + push 后 ls-remote 双通道 sha 核验。

Whitelist add + pathspec commit (never sweeps your staged work) + rebase --autostash + push with ls-remote dual-channel sha verification.

02数据互通02Interoperability

存储就是 memory.jsonl + emb.f32 侧车——Rust memlite CLI 写的库，插件直接读；插件写的库，Rust 直接 recall。同一份记忆，CLI、Harness、未来的 Kimi/ZCode 插件共享。

Storage is plain memory.jsonl + an emb.f32 sidecar — libraries written by the Rust memlite CLI read directly in the plugin and vice versa. One memory, shared across CLI, Harness, and future Kimi/ZCode plugins.

06M0 实测记06Field notes

0.1.0 在 dsh 0.2.2-rc.1 真机验证，四处 API 与旧文档不符——全部实测坐实并回写方案。这也是本插件与「mock 测试通过、真机失败」路线的区别。

0.1.0 was verified on a real dsh 0.2.2-rc.1 host; four APIs differed from older docs — all confirmed on the machine and written back into the proposal.

  • credentials.resolve(ref) 返回 {value, source}——不是 get(ref)。returns {value, source} — not get(ref).
  • AssembleContext 类型面无 agent 字段，运行时实传 {agent, scope, signal}——防御性读取。has no agent field in types, but the runtime passes {agent, scope, signal} — read defensively.
  • 无 providers 服务No providers service ——dsh-llm 只有 chat，无 embeddings；host 档明示回退。— dsh-llm is chat-only; the host tier falls back explicitly.
  • COMMAND_NAME 单 token 正则——命令名含空格注册即拒。is a single-token regex — spaced names are rejected at registration.
