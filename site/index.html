01它做什么What it does

六个机制，全部落在你自己的机器上。

Six mechanisms, all on your own machine.

🧠

pre-step 召回

pre-step recall

每轮在 agent/pre-step 同步召回，按条数/阈值/字符预算裁到标题级，以 source=memlite 的 user 消息追加——零 tool 调用。正文按需用 memlite_show 展开。

Synchronous recall in agent/pre-step: trimmed by count/threshold/char budget to title level and appended as a source=memlite user message — zero tool calls. Expand bodies on demand with memlite_show.

🌳

因果树

Causal tree

记忆是父子链：父=因、子=果。命中即见前因后果，防环 64 层封顶；/memlite-chain 一把取回整条链。

Memories form parent-child chains: parent = cause, child = effect. Hits show their causes and effects; cycles capped at 64 levels; /memlite-chain retrieves a whole chain.

⚙️

GUI 配置页

GUI settings

侧栏「插件」→ Memlite 记忆行 → 配置。插件自带浏览器半区，表单暂存草稿、只读生效值，保存才写入 profile 的 cordis.patch.yml；召回参数即时生效，目录/嵌入/同步变化自动重建引擎。

Sidebar → Plugins → the Memlite Memory row → Configure. The plugin ships its own browser half: the form stages a draft, shows effective values, and only Save writes the profile's cordis.patch.yml. Recall parameters apply live; directory/embedding/sync changes rebuild the engine.

🛡️

敏感闸

Sensitive gate

写前扫描明文口令、API 密钥、身份证、银行卡（Luhn）、手机号、JWT、PEM 私钥——命中即拒，提示改存位置指针。

Pre-write scan for plaintext passwords, API keys, ID numbers, bank cards (Luhn), phone numbers, JWT, PEM keys — hits are rejected with a pointer suggestion.

📝

Obsidian 桥

Obsidian bridge

配置页的 Obsidian 桥 可直接预览/导入 vault、把记忆库导出为 vault、检查 synced/outdated/missing；/memlite-import、/memlite-export 做同样的事。单向工具，不是双向同步。

The Obsidian bridge in the settings page previews/imports a vault, exports the library as a vault, and checks synced/outdated/missing states; /memlite-import and /memlite-export do the same. One-way tools, not two-way sync.

🔄

git 同步

Git sync

白名单 add + pathspec commit（不卷走你已暂存的改动）+ rebase --autostash + push 后 ls-remote 双通道 sha 核验。

Whitelist add + pathspec commit (never sweeps your staged work) + rebase --autostash + push with ls-remote dual-channel sha verification.

02互通与取舍Interop & trade-offs

存储就是 memory.jsonl + emb.f32 侧车——Rust memlite CLI 写的库，插件直接读；插件写的库，Rust 直接 recall。同一份记忆，CLI、Harness、AstrBot 共享。

Storage is plain memory.jsonl + an emb.f32 sidecar — libraries written by the Rust memlite CLI read directly in the plugin and vice versa. One memory, shared across the CLI, Harness, and AstrBot.

同门的 respire-dsh 是另一条产品线：它驱动 rsrs 加密引擎，本插件用进程内 memlite 引擎；数据格式不互通，按下面的取舍二选一。

Its sibling respire-dsh is a separate line: it drives the encrypted rsrs engine, while this plugin runs the in-process memlite engine. The data formats do not interoperate — choose one by the trade-offs below.

060.3.1 实测记Field notes

从 0.1.0 的 API 漂移，到 0.3.1 的 GUI 配置页与展示名——每一条都先在真机坐实，再回写代码与文档。

From the 0.1.0 API drifts to the 0.3.1 GUI settings page and display name — every item was confirmed on a real host before being written back into code and docs.

  • GUI 配置页GUI settings page 真机用 UI 自动化验证：把 recallLimit 改成 6 保存，profile 的 cordis.patch.yml 出现 - id: memlite / config: recallLimit: 6；改回 5 保存，覆盖被 unset 移除。verified with UI automation: setting recallLimit to 6 wrote - id: memlite / config: recallLimit: 6 into the profile's cordis.patch.yml; setting it back to 5 removed the override via unset.
  • volatile 投影Volatile projection settings 只投影 .volatile() 字段，且同一 schema 内不允许嵌套 volatile——所以根 Config 整体 volatile，插件按次读快照。settings projects only .volatile() fields and forbids nested volatile inside one schema — so the root Config is volatile and the plugin reads a snapshot per call.
  • 展示名称Display name 来自 locale/<lang>.json 的 meta.title/meta.description；包有 exports 时必须导出 ./locale/*.json，否则静默回退包名。bundle 卡片与行共用同一份 meta。comes from meta.title/meta.description in locale/<lang>.json; when the package declares exports, ./locale/*.json must be exported or it silently falls back to the package name. Bundle cards and rows share the same meta.
  • 重载方式Reloading a row 本 profile 下 set_plugin 对 bundle 内行返回 overridden 且不生效；用 set_bundle 关/开组合包，行才会重启并重读 manifest 与客户端 bundle。on this profile set_plugin reports overridden for a row inside a bundle and does nothing; toggling the bundle with set_bundle restarts the row and re-reads its manifest and client bundle.
  • credentials.resolve(ref) 返回 {value, source}——不是 get(ref)（0.1.0 实测）。returns {value, source} — not get(ref) (0.1.0 finding).
  • AssembleContext 类型面无 agent 字段，运行时实传 {agent, scope, signal}——防御性读取。has no agent field in types, but the runtime passes {agent, scope, signal} — read defensively.
  • 无 providers 服务No providers service ——dsh-llm 只有 chat，无 embeddings；host 档明示回退。— dsh-llm is chat-only; the host tier falls back explicitly.
  • COMMAND_NAME 单 token 正则——命令名含空格注册即拒。is a single-token regex — spaced names are rejected at registration.
