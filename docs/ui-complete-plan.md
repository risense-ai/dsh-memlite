# dsh-memlite 完整 UI 设计方案与实施计划

> 日期：2026-11-08  
> 基线：`@rsrsai/dsh-memlite@0.4.0`（HEAD `2e947da`）、DSH `0.2.2-alpha.2`  
> 输入：[`artifacts/dsh-market-头部插件-DSH-UI-调研-20261108.md`](../../artifacts/dsh-market-头部插件-DSH-UI-调研-20261108.md)、`/tmp/dshmarket/shots/` 21 张官方截图、当前源码与 M8 真机截图  
> 本文是后续实施规格。**实施状态（2026-11-08）**：M9a–M12 已在 0.5.0 落地，
> 包括 `@rsrsai/memlite@0.2.0` 条件写、四视图、写入闭环、逐条解释/反馈、状态/同步/Obsidian 收口。
> 唯一裁剪：**聊天回复内嵌入口**因宿主没有稳定的回复操作栏 slot，未挂载，仅保留右侧入口；
> 没有伪造宿主挂载点，也没有虚构 pending/撤销删除/永久审计/自动调权。

## 1. 结论

在现有右侧栏三视图之上，做成 **“对话可解释、记忆可修正、因果可追踪、运行可诊断”** 的完整闭环：

- **保留三个高频视图**：本次对话、全部记忆、因果树；不照搬 mnemon 的多 Provider、多记忆空间与技能市场。
- **新增第四个“状态”视图**：集中本地库、检索降级、同步、Obsidian 和近期写入回执。
- **聊天附近提供轻量入口**：回复后的“本回合记忆”和“存入记忆”，详情仍落在右侧栏，避免卡片侵入消息流。
- **写操作走主类和读回校验**：存入、编辑、改挂、忘记都产生统一回执；浏览器不直写 JSONL。
- **不虚构能力**：引擎没有 `pending`、合并、自动审批、撤销删除、反馈调参，就不在 UI 声称拥有。

设计主线是“轻量嵌入、因果可见”，不是“另一个重型记忆管理后台”。

## 2. 已核实的现状与差距

### 2.1 已有，可直接扩展

| 现状 | 代码依据 | 设计用法 |
|---|---|---|

| 本地库状态、敏感闸、BM25/RRF 降级 | `src/format.ts`、`src/schema.ts`、memlite-js `memlite.ts` | 状态页展示真实后端和降级，不把本地等同加密 |
| Obsidian 预览/导入/导出及单任务互斥 | `src/obsidian.ts`、`src/client/MemliteSettings.tsx` | 保留表单，增加结构化报告、任务状态和入口 |
| 中英 locale、DSH 主题变量、纯文本正文 | `src/client/memory-locales.ts`、M8 contract | 继续遵守，无 HTML 注入、无独立主题 |

### 2.2 主要缺口

1. 浏览器只读，用户发现错误后必须记命令才能修正。
2. `mem.update()` 是末写胜出（LWW），当前公开 `MemRecord` 无版本字段；直接做 GUI 编辑会覆盖并发修改。
3. 召回账本只有分数、阈值和预算结果，无法完整解释“为什么没召回”；不能假称 querylog 反馈会自动调权。
4. 记忆被删后，历史召回只剩标题快照；没有可审计的写入历史或撤销能力。
5. 状态、同步和 Obsidian 分散在命令与插件设置，没有统一的运行视图。
6. 当前窄栏可用，但新增写操作后需要明确列表—详情—编辑器的宽度切换，不能继续堆叠卡片。

## 4. 体验原则与视觉规则

1. **一处入口**：聊天入口、Guide、右侧 Memory 共用同一记忆图标；DSH 数据库图标仍只表示用量。
2. **一个动作名**：所有入口都叫“存入记忆”“编辑记忆”“改挂因果”“忘记记忆”，成功语义一致。
3. **名称优先**：默认展示标题，id 收在“技术详情”；需要复制时再显示。
4. **证据分层**：候选 ≠ 已注入；本地 JSONL ≠ 已加密；嵌入已配置 ≠ 本次使用语义检索；同步完成 ≠ 远端已验证。
5. **就地回执**：操作按钮原位进入 busy，结果留在当前卡片；跨入口的最近回执同步出现在状态页。
6. **一个刷新**：只在面板顶栏；写成功引起的局部更新不算第二个手动刷新入口。
7. **破坏性才用红色**：忘记、覆盖导出需确认；阈值/降级用中性或警示色，不用错误红。
8. **无活动不打扰**：无记忆回合不显示聊天折叠条；空态给下一步，不堆指标。
9. **宿主优先**：继续复用 React、locale、`--dsw-*`、原生按钮/输入/选择器，不引入 UI 框架或图谱库。
10. **安全默认值**：敏感闸默认开；不因 UI 可编辑而新增绕过开关，不显示密钥、向量、原始提示词或任意 `extra`。

### 4.1 排版与布局

- 沿用宿主字体，不新增字体。正文 14px/1.55，辅助文字 12–13px/1.5，区块标题 16px/1.3；行高改 unitless。
- 侧栏最小支持 **320px**；360–520px 单列，详情作为面板内下一层，可返回且保留列表滚动位置。
- ≥720px 悬浮/全屏时列表 280–320px + 详情自适应；状态卡两列；≥1100px 最多三列，禁止无意义铺满。
- 长文正文最大 65ch，`white-space: pre-wrap; overflow-wrap: anywhere`；摘要最多两行，完整内容总在详情可达。
- 计数、分数、时间用 `font-variant-numeric: tabular-nums`；标题可换行，徽章不换行，长 id 用 `<bdi>`。
- 键盘焦点可见；触控目标至少 32×32px，主要按钮 40px；弹窗支持 Escape、焦点圈定与关闭后焦点还原。
- 中英文、200% 缩放、320px 宽均无横向溢出。移动 Safari 若进入支持范围，输入字号 16px；当前桌面侧栏不另做移动 App。

## 5. 完整信息架构与界面线框

### 5.1 面板骨架

```text
记忆                         [本地·可用⌄] [＋ 存入] [↻] [⚙]
[本次对话] [全部记忆] [因果树] [状态]
────────────────────────────────────────────────────
当前项目：risense ⌄     范围只影响浏览；保存项目由会话决定
────────────────────────────────────────────────────
视图内容
────────────────────────────────────────────────────
统一回执（有操作时显示）      N 条 · 最后更新 10:54
```

- 顶栏状态是按钮，点击直达状态页；显示“本地·可用 / 词面检索 / 有警示 / 已禁用”，不笼统显示“已连接”。
- “＋存入”在启用且引擎可写时出现；禁用时不允许先填一大段再报错。
- 项目筛选标签明确“浏览范围”；不伪造一个与实际 `dataDir` 不一致的“全局/项目库切换器”。

### 5.2 本次对话：从“看到命中”到“理解并修正”

```text
第 3 回合 · 10:54          已注入 2 / 候选 3 · BM25 · 4 ms
▸ [实际注入原文]
  ① nginx 504 根因与处置              已注入 · 分数 5.47
     为什么：超过阈值 0；标题预算内
     [查看] [这条有帮助 / 不相关]
  ② 504 现象与时间分布                预算截断
     为什么：前 2 条已用 1,476 / 1,500 字符
     [查看] [调整预算]
  ③ 本周发布约定                      低于阈值
     为什么：0.18 < 0.30
```

- 回合摘要只显示实际注入数、候选数、后端和耗时；默认展开最近回合。
- 每条解释必须来自结构化 `RecallTitleSelection`；文案是规则的直接映射，不由模型生成。
- “实际注入原文”只保存本轮真正生成的标题块，不保存原始用户提示词；没有则显示“本回合未注入”。
- 零命中、短提示、`/nomem`、敏感闸、显式存储、失败均各有原因；显式存储产生的写入回执也归入本回合。
- 好/坏按钮是显式评价；默认未评价。第一版只用于统计和导出诊断，**不自动调 BM25 权重**。
- 内存账本重载清空时写“仅本次运行可见”，不称“完整历史”。

### 5.3 全部记忆：浏览、检索、编辑同一选中态

```text
[搜索标题、正文、标签……                 ]
[当前项目⌄] [全部标签⌄] [重要性⌄] [最近更新⌄]
已启用筛选：dsh-memlite ×                共 11 条

┌ 列表（窄栏整行） ───────────────────────┐
│ nginx 504 根因与处置                    │
│ 504 先区分上游超时与主动断连……          │
│ dsh-memlite · 重要 · 2 个子条 · 10:42   │
└─────────────────────────────────────────┘

详情（选中后；宽屏右侧，窄栏下一层）
← 返回列表     nginx 504 根因与处置
[重要] [dsh-memlite] [#nginx] [#incident]
正文……
前因：网关改造决策  ›    后续：504 处置步骤  ›
[编辑] [基于此续写] [改挂因果] [复制⌄] [忘记]
```

- 默认最近更新；检索时相关度排序；宽屏可切换“时间线”分组，不新增一个顶级 tab。
- 徽章最多保留项目、重要性、子条数；标签和完整时间放详情，避免现有卡片信息过密。
- “基于此续写”打开存入编辑器并预选当前条为 parent；这是因果树的自然写入口。
- 忘记确认展示标题、子条数及“会留下删除标记，当前版本不可撤销”；不误导为归档。
- 编辑保存前带 `expectedTs`；版本冲突显示当前版本与用户草稿，提供“重新载入”“复制我的草稿”，不静默覆盖。

### 5.4 因果树：围绕问题组织，不追求图形炫技

```text
[当前项目⌄] [搜索树内标题……]   根节点 7 · 已展开 12
▼ nginx 504 根因与处置              重要 · 2 个子条
   ├─ 504 现象与时间分布             琐碎
   └─ 504 处置步骤                   重要 · 1 个子条
▶ 召回注入机制                       重要 · 2 个子条
────────────────────────────────────
选中：504 处置步骤
[查看全文] [围绕它检索] [基于此续写] [改挂因果]
```

- 保留逐层加载、断链/环提示；增加“定位选中节点”和“展开到当前记忆”，避免跨视图跳转后丢上下文。
- “围绕它检索”使用标题及用户可编辑的补充词，跳全部记忆并保留项目范围；不是假称图遍历语义搜索。
- 树节点只显示标题、重要性、子条数；技术 id 收进详情。
- 宽屏全屏后续可做“按时间着色”的辅助模式；力导向图/星空不在 M9–M12。

### 5.5 状态：只显示可行动的信息

```text
本地记忆库                     ● 可用 · 11 条 · 0 坏行
数据位置：项目级 .memlite（完整路径仅在“技术详情”中按需显示）
[打开全部记忆]

检索                          BM25 · 默认零外网
嵌入：未启用                  本次运行：0 次降级
[打开检索设置]

同步                          未启用 / 未配置 / 已验证 分开显示
[立即同步]  结果：committed / local_sha / remote_sha / verified

Obsidian 互通                  无任务运行 / 正在扫描 / 最近结果
[检查 Vault] [预览导入]  导入前默认 dry-run

近期回执                      存入 2 · 更新 1 · 失败 0
[查看当前会话] [复制诊断摘要]
```

- 页首只放“需要处理”的横幅；正常状态不堆六张卡。
- 健康检查分为：空库（提示，不是故障）、坏行、断链、嵌入缺失/失败、同步未验证、Obsidian 失败。
- 健康检查只报告，不自动修；修复跳对应记忆或设置。
- 诊断摘要只含版本、计数、后端、错误码和配置非敏感项；不含正文、原始提示词、凭据、远程 token 或完整私人路径。

### 5.6 存入/编辑弹层

在窄侧栏用面板内整页，在宽屏用宿主对话框；字段与行为相同。

```text
存入记忆                       当前项目：risense
标题（事实句） [____________________________]
正文           [____________________________]
               [____________________________]
标签           [incident, nginx             ]
重要性         (●) 可复用结论  ( ) 过程记录
前因           [可选：搜索并选择一条记忆……]
               不选择则保存为根节点
[取消]                                  [存入记忆]

回执：✓ 已存入并读回核对 · 向量已更新/未启用
[查看记忆] [继续编辑]                       [完成]
```

- 默认项目从会话上下文获得并明确显示；不能由客户端任意传绝对 `dataDir`。
- 敏感信息命中时保留草稿，指出类别，不回显秘密，不自动反复提交。
- 嵌入异步失败不抹掉 JSONL 已保存事实；显示“已保存；语义索引待回填”，并给 reembed 入口。
- 标题、正文、项目、标签、重要性、前因都按白名单校验；`kind` 只允许受控枚举或留空，不开放任意 `extra`。

### 5.7 聊天附近入口（需先做宿主 spike）

```text
助手回复……
⌄ 本回合记忆 · 注入 2 / 候选 3       [查看]
复制  赞  踩  [脑形 存入记忆]  分享
```

- 默认折叠，最多预览 3 条；点击打开右侧“本次对话”并定位回合。
- “存入记忆”预填选中文本；无选中文本时可预填当前回复，但用户必须编辑确认。
- 不调用任务 Agent，不自动提炼整段回复，不阻塞当前对话。
- 若 DSH 没有稳定的回复操作栏/回复尾部 slot 及会话路由接口，M9 只保留右侧入口，记录宿主阻塞，**不改宿主源码伪造挂载点**。

### 5.8 设置与 Obsidian

设置继续留在插件详情，不重复塞进侧栏。分组调整为：

1. **基本**：总开关、数据目录、敏感闸；每项写明是否重建引擎。
2. **召回**：条数、阈值、字符预算、短提示跳过、收尾提醒；注明“只影响新请求，已显示的召回账本不改写”。
3. **嵌入**：none/openai-compatible/host；host 不可用时明示原因，不以可选项伪装可用。
4. **同步**：默认关，说明 git 白名单、明文 JSONL 和远端风险；绝不展示凭据。
5. **Obsidian**：状态、预览、导入、导出。结构化显示 scanned/created/updated/unchanged/skipped/warnings；路径仍只在主动操作中处理。
6. 顶部增加“打开记忆浏览器”，保存后显示“已生效/需重载/保存失败”，不笼统写“即时生效”。

## 6. 统一状态与回执词典

### 6.1 写入回执

| UI 文案 | 使用条件 | 禁止表达 |
|---|---|---|
| 已存入并读回核对 | 新建成功，id/标题/正文一致 | “已同步”“已被模型采用” |
| 已更新并读回核对 | 更新成功且读回一致 | “覆盖了并发版本” |
| 已改挂因果 | attach 成功且父链读回一致 | “已建立语义关联” |
| 已忘记 | del 墓碑成功且当前 show 不存在 | “已归档”“可撤销” |
| 已保存；语义索引待回填 | JSONL 成功但嵌入失败/未启用 | “写入失败”或“语义检索已包含” |
| 已跳过 | 空内容、无变更、明确用户取消等 | 把跳过当成功 |
| 部分完成 | 批量 Obsidian 中确实有成功也有失败/跳过 | 单条写操作不得滥用 |
| 未保存 | 敏感闸、校验、冲突或写入异常 | 删除草稿或自动重试 |
| 保存结果待核实 | 已发出写请求但连接中断，无法判断是否落盘 | 直接再写一遍；先 show/list 核实 |

当前引擎没有 `pending` 审批状态，因此第一版词典不采用“已提交等待确认”。未来真引入 pending 域后再增加，不以文案代替数据模型。

### 6.2 召回解释

| 状态 | 解释来源 |
|---|---|
| 已注入 | `injected=true`，标题块进入 decision.messages |
| 低于阈值 | `exclusion=threshold`，显示当时分数与阈值 |
| 预算截断 | `exclusion=budget`，显示当时预算与实际使用值 |
| 零命中 | `status=empty`，不猜“没有相关事实”之外的原因 |
| 已跳过 | `skipReason=nomem/short/sensitive/store/disabled` |
| 检索降级 | `backend/fallback`，展示实际后端和项目→用户回退 |
| 失败 | 安全错误码；不展示原始 prompt、密钥或路径 |

“未进入候选”的全库排除原因需要新增有界候选诊断；没有该数据前不得写“因 RRF 排名靠后”。

### 6.3 写入统一数据结构（建议）

```ts
type MemoryWriteKind = 'remember' | 'update' | 'attach' | 'forget'
type MemoryWriteStatus =
  | 'saved' | 'saved-degraded' | 'skipped' | 'partial'
  | 'rejected' | 'conflict' | 'failed' | 'unconfirmed'

interface MemoryWriteReceipt {
  operationId: string            // 单次客户端操作 uuid
  kind: MemoryWriteKind
  status: MemoryWriteStatus
  id?: string
  title: string
  verified: boolean
  embedded: 'updated' | 'disabled' | 'pending' | 'failed' | 'not-applicable'
  code?: string                   // 稳定错误码，不把异常原文直接当协议
  timestamp: number               // 秒
}
```

内存保存最近 100 条，按会话/agent 隔离；重载清空。它不是永久审计日志，永久审计另立需求。

## 7. 数据与接口方案

### 7.1 先解决并发，再开放编辑

`MemRecord` 当前只有 `ts`，`update()` 直接 LWW；M9 不能直接发送“id + 新正文”。

- **近期契约**：详情/列表投影增加只读 `ts`；写请求带 `expectedTs`。Host 在共享 Memlite 实例内先 resolve 并比较，再写、再读回。
- **必须承认的限制**：memlite-js 目前没有条件写 API，进程内“比较后写”与 CLI/其他宿主并发仍存在检查—写入间隙。M9 第一步应在 memlite-js 增加原子条件写/版本守卫；在此之前只开放新建，编辑/改挂/忘记不得宣称并发安全。
- 条件写冲突返回 HTTP 409 + `code=STALE_VERSION` + 当前安全投影；草稿留在客户端。
- `ts` 若不足以作为唯一版本，新增 opaque `revision` 投影，但不得破坏 Rust/TS JSONL 互通；先做格式 spike 和互通测试。
- Obsidian 与 UI 共用同一 Memlite 实例和互斥机制；导入/导出中相关编辑返回 409，不并行写库。

### 7.2 路由增量

沿用 `POST api/memlite/browser/*`、64 KiB 请求上限、认证、Origin/owner 校验、安全错误和 `engine` 代次。正文按 UTF-8 字节校验，超限直接拒绝并保留草稿；一条记忆必须原子保存，不能分页写入。

| 路由 | 用途 | 关键约束 |
|---|---|---|
| `status` | 本地库、检索、同步、近期回执 | 默认不返回完整路径/远程 URL/凭据引用 |
| `remember` | 新建并读回 | operationId 幂等；敏感闸；父存在；项目白名单 |
| `update` | 编辑标题/正文/标签/重要性 | expectedTs/revision；读回；无变更=skipped |
| `attach` | 改挂或升根 | expected 版本；防自挂/防环；重读父链 |
| `forget` | 删除 | expected 版本；confirmTitle；返回删除验证 |
| `recall-feedback` | 对某个 session turn + memory id 作好/坏评价 | 仅允许账本已有 id；不接收任意正文；不自动调权 |
| `sync` | 显式触发 git 同步 | UI 不提交 remote 字符串；结果四字段；互斥 |
| `reembed` | 显式回填 | 进度有界、可中止；失败计数；不阻塞 pre-step |

`Obsidian` 继续走现有三条路由，新增结构化 `report` 字段而保留 `text` 兼容；大 vault 进度需服务端任务句柄，不能靠按钮假进度。

### 7.3 账本扩展

在不保存原始提示词的前提下，增加：

```ts
interface SessionRecall {
  // 既有字段保留
  injectedText?: string       // 实际标题块，受 budgetChars 上限
  threshold?: number
  budgetChars?: number
  usedChars?: number
  limit?: number
  elapsedMs?: number
  feedback?: Record<string, 'helpful' | 'irrelevant'>
}
```

- `injectedText` 只包含标题、分数和 id8，不含记忆全文；若未来包含正文需重新做隐私审查。
- 配置修改不改写历史快照；历史回合显示当时阈值/预算。
- 会话/agent 切换、插件禁用、引擎重建、请求 abort 沿用现有清理规则。
- querylog 不直接暴露给普通 UI；反馈是否落盘另做数据格式决策，首版仅存内存并明示重载清空。

### 7.4 前端拆分

避免继续把功能塞入 1,800 行组件：

```text
src/client/memory/
  MemliteMemory.tsx          容器、视图路由、共享选中态
  MemorySessionView.tsx      回合与解释
  MemoryLibraryView.tsx      搜索、筛选、时间线
  MemoryTreeView.tsx         树与定位
  MemoryStatusView.tsx       健康、同步、Obsidian 摘要
  MemoryEditor.tsx           新建/编辑/续写共用
  MemoryReceipt.tsx          统一回执
  memory-api.ts              校验、abort、幂等 id
  memory-locales.ts          中英完整词典
src/memory-write-service.ts  Host 写服务：守卫→条件写→读回→回执
src/memory-status.ts         安全状态投影
src/recall-explain.ts        与 selectRecallTitles 同源的纯解释映射
```

浏览器 bundle 仍只外部依赖 React；无 UI 库、无图库、无宿主运行时 import。正文继续纯文本渲染。

## 9. 验收矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| 新建成功 + none 嵌入 | 已存入并读回核对；标“语义未启用”；BM25 可检索 |
| 新建成功 + 嵌入失败 | 已保存；语义索引待回填；不重复写 JSONL |
| 敏感内容 | 未保存；只报类别；草稿保留；日志/响应不含秘密 |
| 两个窗口编辑同一条 | 后提交者 409；两个草稿均可恢复；无静默 LWW |
| 忘记有子条记忆 | 明示影响、confirmTitle、删除后详情/树/召回历史状态一致 |
| 请求成功后断线 | 保存结果待核实；先按 id/operationId 查询，不自动二次写 |
| 阈值/预算 | 候选未注入有明确原因；实际原文与 decision.messages 一致 |
| `/nomem`/短输入/敏感输入 | 不显示空泛失败，显示对应跳过原因 |
| 会话与项目切换 | 不串账本、反馈、详情、草稿或回执 |
| 同步未配置/失败/未验证 | 三种状态不同，不出现“已同步”泛成功 |
| Obsidian 空路径/重入/部分失败 | 拒绝/409/部分完成各自明确；不自动重试写操作 |
| 插件禁用/引擎错误 | 禁用 503 + disabled；异常 500 可重试；编辑器不误导可写 |
| 320px + 200% + 英文 | 无横向溢出，所有正文/按钮/错误仍可达 |
| 卸载/配置重建 | abort 请求、清理账本和失效详情，不读写旧引擎 |

## 10. 风险、边界与待验证项

| 项 | 处理 |
|---|---|
| DSH 聊天挂载 API 不存在或变动 | M9a spike；失败则只做右侧入口，不改宿主、不假设 slot |
| LWW 与跨进程并发 | 上游条件写先行；不能落地则关闭编辑/改挂/忘记，仅开放新建 |
| JSONL 明文与 git 同步 | 状态/设置明确“本地不等于加密”，凭据引用和路径不进入诊断 |
| 记忆正文包含不可信指令 | 仅作历史证据；正文纯文本，编辑器不执行其中 HTML/命令 |
| 大库性能 | 保持分页/逐层加载；状态聚合有界；反馈和诊断不读全量正文 |
| 进度与审计造假 | 没有任务句柄不显示百分比；内存账本明示重载清空 |
| 反馈泡沫 | 先记录与统计，只有离线验证有效后才另立 rerank/调权方案 |
| 组件膨胀 | M9 拆分视图与共享写服务，不在现有大组件继续堆条件 |

明确不在本轮方案：力导向/星空图、自动提炼与自动审批、技能市场、多 Provider 空间、撤销删除、永久审计、自动反馈调权、独立移动 App。
